# Codex Migration Hardening Design

**Status:** Approved for implementation by the user on 2026-09-13.

**Goal:** 把 0.2 预览版提升为可验证的 Codex 重装迁移工具：备份前能判断是否达到可重装条件，恢复后能分别证明文件结构完整和 Codex 应用可用，并保留安全边界。

## 现状与边界

当前版本已经读取 `CODEX_HOME`、配置、项目登记、会话引用、SQLite、外部记忆、技能和 Git 依赖，支持多盘符、搬迁映射、完整迁移、抢救模式、严格 Core schema 检查、暂存和回滚。当前版本仍是 preview：真实新 Windows、真实 Codex 登录及完整应用层恢复尚未验收。

完整迁移的定义只覆盖本次扫描实际发现且可读的本地文件及关联。缺失源码、缺失转录、未读完整元数据、活动写入者、未知 Core schema 和扫描上限都必须阻止“可重装”结论。WSL、Docker、网络位置、远程数据库、其他 Windows 用户、云端数据和未知未来字段继续作为明确的范围外项目。

## 目标行为

### 发现与最终判定

- 扫描继续以配置和引用为主，不用固定 C 盘启发式替代配置解析。
- 发现结果同时显示来源记录数、独立会话 ID 数、会话关联数、项目位置数和覆盖磁盘。
- 备份前生成一份持久化 preflight 报告，状态只能是“可以重装”“需要处理后再重装”或“仅可抢救”。
- 报告逐项列出缺失源码、缺失转录、受限元数据、WAL 不确定性、活动进程、未扫描位置和用户必须补充的目录。
- 完整迁移继续 fail-closed；抢救模式可以保存剩余内容，但永远不升级为完整包。

### Core 与版本

- 备份清单保存来源 Codex 版本、安装来源和发现证据。
- 恢复界面显示来源版本与目标版本，版本未知或不兼容时默认只允许隔离解出。
- 多套 Core 必须由用户明确选择一个主 Core 映射到当前 `CODEX_HOME`，其余 Core 使用独立目录保存，不合并 SQLite。
- Core 受控适配继续要求已识别的 schema/migration fingerprint；未知结构只允许隔离副本。

### 环境与敏感信息

- 导出运行环境清单：语言和包管理器版本、锁定文件、虚拟环境提示、环境变量名称、Windows 服务、计划任务、监听端口、WSL、Docker、Git LFS/子模块、CUDA/本地模型和文件关联。
- 默认不保存密钥值、令牌、Cookie、私钥和密码；敏感文件清单只展示文件名、类别和风险。
- 提供可选的跨系统密码加密包，密码不落盘；同用户 DPAPI 只保护本机回滚日志。
- 配置、凭据、技能、插件和自动化恢复后先进入停用区，提供逐项审核和手动启用记录。

### 恢复后验收

- 恢复完成后生成结构验收报告：会话 ID/转录对应关系、`cwd`、项目根、Git 指针、记忆指针、路径冲突、长路径、大小写和 Unicode 路径。
- 结构验收和应用验收分开显示。应用验收由用户在隔离或新系统中确认登录、侧栏、会话打开、项目打开、未提交代码、记忆、技能和代表性项目运行。
- 历史对话正文不做全局路径替换；任何未改写字段必须在报告中明确说明。

### 可理解性与运维

- 面向普通用户的提示只使用原因、影响和下一步；异常类型名和堆栈只能放在折叠的技术详情。
- 中断或崩溃后的 `.incomplete`、`.stage`、`.rollback`、`.original` 和 `.undo` 目录要有生命周期提示和二次校验后清理入口。
- 发布包使用统一版本常量、release manifest、SHA-256 和 Windows Authenticode 签名（签名证书可用时）。

## 设计结构

`DiscoveryService` 负责扫描、来源证据、计数和环境清单；`MigrationCoverage` 负责完整性与 preflight 结论；`BackupManifest` 保存版本、计数、环境和敏感信息摘要；`RestorePlanner` 负责主 Core、目标版本和路径映射；`RestoreEngine` 负责暂存、结构验收和回滚；`PackageVerifier` 负责加密包或普通包的完整性验证；WPF 仅负责向导状态、普通用户文案和报告展示。

## 错误处理

所有不能确认的内容默认降级为阻断或未知，不静默跳过。目标路径冲突、活动写入者、空间不足、非 NTFS、特殊文件、未知 schema、坏包、加密包密码错误和结构验收失败都必须在写入前阻止。任何已发生的写入都必须有可验证的回滚记录。

## 测试与发布门槛

先为每个行为增加失败测试，再实现最小改动。测试覆盖配置自定义目录、多个 Core、版本不兼容、计数语义、环境清单脱敏、加密包、异常文案、恢复结构验收、中断清理和旧包兼容。

最终发布前必须完成：源码回归全绿、EXE 自检、WPF 导航 smoke、实际用户只读扫描、隔离环境恢复、真实 Codex 应用验收记录、备份包二次校验和发布清单。未完成新系统应用验收时，版本必须继续标记为 preview。
